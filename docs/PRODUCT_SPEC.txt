這個專案很適合做成真正的「simulation product」，而且它的亮點不應只是「很多小生物在跑」，而是：

> **每一個物種、每一項性狀、每一次滅絕，都能追溯到真實執行過的遺傳、競爭、環境與繁殖事件。**

我會把它定位成 **Evolution Sandbox × Artificial Life × Interactive Natural History Museum**。

---

# 0. 產品定位

暫定產品名可以先維持：

**AI 生態箱 / Project GENESIS**

產品的核心不是「操控單位」，而是：

> **改變世界 → 形成選擇壓力 → 觀察族群適應 → 產生分化 → 建立演化歷史 → 回頭研究演化原因。**

玩家扮演的更接近：

**生態系統設計者 / 觀察者 / 實驗者。**

不是上帝直接讓某隻動物變快。

玩家只能改環境。

例如：

```text
Generation 8,100
平均氣溫：21°C
主要食物：低矮植物

↓ 玩家讓北方逐漸降溫

Generation 11,400
北方族群：
- 體型 +17%
- 基礎代謝 -8%
- 視覺半徑 -11%
- 脂肪儲備 +24%

Generation 12,481

Velocipodus ruber
          │
          ├── Southern lineage
          │
          └── Velocipodus borealis
                ↑
             新物種
```

重點是這些結果不是腳本。

# 1. 核心玩法與最重要差異化

## 核心 gameplay loop

完整循環應該是：

```text
建立世界
   ↓
放入最初生命
   ↓
模擬
   ↓
觀察
   ↓
改變環境
   ↓
形成新的 selection pressure
   ↓
突變 / 繁殖 / 死亡
   ↓
族群性狀改變
   ↓
生態位形成
   ↓
物種分化 / 滅絕
   ↓
查看 Evolution Tree
   ↓
分析「為什麼」
   ↓
再干預
```

### 玩家控制

只允許控制環境層：

- 溫度
- 溫度梯度
- 水域
- 山地
- 平原
- 森林
- 土壤
- 食物密度
- 食物類型
- 日照
- 季節
- 天敵
- 疾病
- 火災
- 洪水
- 乾旱
- 寒潮
- 火山
- 隕石等高階災難

### 玩家不能做

不能：

```text
把 Species A 的 speed 改成 50
```

不能：

```text
讓這個物種獲得夜視
```

不能：

```text
立即進化
```

玩家只能創造：

```text
因為環境變暗
→ 視覺好的個體平均存活率提高
→ 經過大量世代
→ allele frequency 改變
```

這一點要非常嚴格。

# 4. Simulation architecture

simulation 不應跟 frame rate 綁定。

必須：

```text
Render FPS
≠
Simulation ticks
```

結構：

```text
Wall clock
     │
     ▼
SimulationScheduler
     │
     ├── tick 10001
     ├── tick 10002
     ├── tick 10003
     └── ...
```

世界狀態：

```text
WorldState
├─ tick
├─ generation
├─ environment
├─ organisms
├─ resources
├─ species
├─ lineages
├─ events
└─ rng_state
```

---

# 5. Tick pipeline

每一 tick 固定順序。

非常重要。

例如：

```text
1. Environment update
2. Resource regeneration
3. Spatial indexing
4. Perception
5. Intent calculation
6. Movement
7. Feeding
8. Predation
9. Combat
10. Metabolism
11. Damage
12. Death
13. Reproduction
14. Mutation
15. Birth
16. Population statistics
17. Species detection
18. Historical events
19. Telemetry
```

禁止 subsystem 隨便自己修改其他 subsystem。

最好是：

```text
read state
   ↓
produce intent/event
   ↓
resolve
   ↓
commit
```

避免：

```text
Organism A update()
  → immediately kills B
  → B 沒有執行本 tick
```

造成 iteration-order-dependent simulation。

---

# 6. Genome model

Genome 不應只是：

```json
{
  "speed": 10
}
```

那只是 RPG stats。

建議：

```text
Genome
├─ morphology genes
├─ metabolism genes
├─ sensory genes
├─ locomotion genes
├─ reproduction genes
├─ behavior genes
└─ regulatory genes
```

初期可以固定長度：

```text
Genome = 32 loci
```

每個 locus：

```text
Gene {
    allele_a
    allele_b
}
```

Phase 1 暫時甚至可以 haploid / simplified diploid。

但資料格式應允許未來擴充。

---

# 7. Genome → Phenotype

所有 gameplay 性狀從 genome 算出。

例如：

```text
base_speed =
locomotion_gene * body_scale_modifier

vision_radius =
eye_gene *
light_adaptation *
energy_modifier

metabolism =
body_mass *
activity_level *
metabolism_gene
```

重要原則：

> genome ≠ phenotype。

環境也會影響 phenotype。

# 10. Species 不是手動標籤

這很關鍵。

物種要由 simulation 判定。

建議模型：

```text
Population cluster
+
genetic distance
+
gene flow
+
persistence duration
```

例如：

```text
candidate lineage

population >= 50

AND

genetic distance >= threshold

AND

cross-group reproduction
< threshold

AND

condition persists
> 500 generations

→ speciation
```

不要一有 mutation 就：

> New Species!

否則很快會得到幾萬個「物種」。

---

# 11. Lineage ≠ Species

要分開。

```text
Lineage
```

代表血統分支。

```text
Species
```

代表被正式認定的演化族群。

例如：

```text
Species A

├─ Lineage A1
├─ Lineage A2
└─ Lineage A3
```

A3 持續分化後：

```text
Species A
│
└── Species B
```

---

# 12. 物種命名

命名不能依賴 LLM。

必須有 deterministic fallback。

例如：

```text
genus stem
+
morphology root
+
ecological modifier
```

資料庫：

```text
velo    speed
ruber   red
alba    pale
minor   small
major   large
borealis northern
silva   forest
aquaticus water
```

Seed + lineage ID 決定命名。

例如：

```text
Velocipodus ruber
```

名字一旦建立：

**永遠不變。**

LLM 可以額外生成：

```text
Common name:
Northern Ember Runner

Description:
...
```

但 scientific name 不依賴它。

## 可以使用 LLM

LLM 可以負責：

### Naturalist description

例如：

> *Velocipodus borealis* is a compact cold-adapted descendant...

### 「Why did this evolve?」

但不能讓模型自己猜。

先由 simulation 建立：

```json
{
  "temperature_change": -11.4,
  "body_mass_change": 0.18,
  "allele_survival_advantage": 0.148

```

再讓 LLM 把數據解釋成人話。

### Natural history documentary

例如：

> 第 12,000 世代開始，北方冰原擴張……

---

### Species common names

Scientific name：

deterministic。

Common name：

可以 LLM。

---

### Scientist assistant

玩家可以問：

> 為什麼東岸的生物都變小？

LLM 查 telemetry 再回答。

# 14. RNG 設計

不要使用：

```text
rand()
```

到處亂抽。

建立：

```text
SimulationRng
```

並將 RNG algorithm version 存入 save。

例如：

```text
seed
rng_algorithm
rng_version
rng_state
```

甚至更好：

建立 RNG stream：

```text
WORLD
MUTATION
REPRODUCTION
DISASTER
RESOURCE
```

避免某個 UI 功能多呼叫一次 RNG，整個宇宙就完全改變。

# 15. 浮點 deterministic 問題

如果你希望：

> Windows A replay = Windows B replay

simulation authoritative state 不應大量依賴 platform-sensitive floating point。

建議核心數值：

```text
position        fixed point
energy          integer/fixed
temperature     fixed
gene value      integer
probability     integer range
```

例如：

```text
temperature:
1842
=
18.42°C
```

rendering 才轉：

```text
f32
```

這會大幅提高 replay 穩定性。

# 16. 地圖 simulation

Phase 1 建議：

```text
2D continuous world
+
uniform spatial hash
```

例如：

```text
4096 × 4096 simulation units
```

Spatial Hash：

```text
cell 0,0
├ organism 81
├ organism 912
└ food 18

cell 0,1
...
```

避免：

```text
每隻生物檢查所有其他生物
```

從：

```text
O(N²)
```

降到接近局部查詢。

這是之後做到數千甚至數萬 organism 的關鍵。

# 18. Behavior architecture

不要 Phase 1 就讓每隻生物跑 LLM agent。

那會直接摧毀：

- performance
- deterministic
- cost
- replay

Behavior 應是 utility AI。

例如：

```text
hungry
→ seek_food

predator_detected
→ flee

energy_high
→ seek_mate

aggression_high
→ challenge
```

計分：

```text
Eat       0.78
Mate      0.62
Flee      0.12
Explore   0.31
```

取最高 intent。

---

# 19. Reproduction

例如：

```text
energy >= threshold

age >= maturity

mate compatibility >= threshold

distance <= range
```

產生 offspring：

```text
Parent A
     \
      crossover
     /
Parent B

      ↓

OffspringGenome
      ↓
mutation
```

mutation 至少：

```text
point mutation
small additive mutation
rare major mutation
```

未來再做：

- duplication
- deletion
- regulatory changes

---

# 20. Selection 不需要特殊程式

不要寫：

```text
if cold:
   evolve cold resistance
```

這會是假演化。

應該：

```text
cold
↓
high cold tolerance organism consumes less energy / survives longer
↓
has more offspring
↓
genes spread
```

Selection 自然產生。

# AI 生態箱 / Project GENESIS — Phase 1 Development

你現在要開始正式開發一個新的 Windows desktop software project。

這不是 prototype、concept demo 或單純視覺模擬。

目標是建立一個可以持續數年迭代的 deterministic artificial-life / evolutionary ecosystem simulation。

---

# 1. Product Concept

專案暫名：

AI 生態箱 / Project GENESIS

核心概念：

玩家不直接控制生物。

玩家只能改變：

- environment
- terrain
- temperature
- food availability
- predators
- ecological pressure

生物依靠真正的：

- genome
- inheritance
- reproduction
- mutation
- metabolism
- perception
- movement
- competition
- predation
- survival

自行演化。

系統最終必須能產生真正由 simulation data 支撐的：

- species
- lineage
- speciation
- extinction
- evolution tree
- natural history

例如：

Velocipodus borealis

約在 Generation 12,481 從 Velocipodus minor 分化。

這個資訊必須來自 simulation lineage / genome / species system，而不是 LLM 虛構。

---

# 2. Non-Negotiable Principles

以下是架構硬性要求。

## 2.1 Simulation must work without LLM

Simulation core 不得依賴：

- OpenAI
- Claude
- Gemini
- local LLM
- network
- external AI API

完全沒有網路時也必須正常 simulation。

Phase 1 不需要實作 LLM。

但 architecture 不得阻止未來加入 optional AI Naturalist。

---

## 2.2 Determinism is a first-class feature

相同：

- simulation version
- seed
- configuration
- command sequence

必須產生相同 simulation checkpoint hashes。

所有 authoritative randomness 必須走統一 deterministic RNG system。

禁止：

- thread_rng
- Math.random
- JavaScript randomness
- uncontrolled system time randomness

進入 simulation truth。

---

## 2.3 Rendering must not affect simulation

Simulation tick 必須與 render frame 完全分離。

UI FPS 改變不能改變 simulation outcome。

Pause / resize / minimize window 不能改變 simulation truth。

---

## 2.4 Simulation truth must be explainable

任何：

- species
- extinction
- population change
- evolutionary trait change

未來都必須可以從：

- genome
- lineage
- historical events
- telemetry

追溯。

不要建立不可解釋的 random scripted evolution。

---

## 2.5 Do not fake completed systems

禁止為了完成畫面：

- 使用假 species
- hard-code evolution events
- 使用 mock population history 當正式資料
- 用 timer 偽造 speciation
- 用 random name event 偽裝 evolution

Demo UI 所看到的資料必須來自真正 simulation。

Test fixtures 可以存在，但必須明確只存在 tests / fixtures。

# 9. Simulation Tick Pipeline

建議順序：

2. resource regeneration
3. rebuild/update spatial index
4. perception
5. intent evaluation
6. movement resolution
7. feeding
8. predation/combat
9. metabolism
10. health/damage
11. deaths
12. mate matching
13. reproduction
14. crossover
15. mutation
16. births
17. lineage/population accounting
18. species detection
19. historical events
20. telemetry
21. checkpoint hash if required

實際順序可以因 implementation 調整。

但：

- 必須明確記錄
- 必須 deterministic
- iteration order 不得偷偷影響 outcome

不要讓 entity update() 直接隨機修改整個 world。

優先採用：

read state
→ generate intent/event
→ deterministic resolution
→ commit

# 17. Reproduction

- maturity

- proximity
- compatibility

Offspring genome：

parents
→ crossover/inheritance
→ mutation
→ genome
→ phenotype

Child 必須保存 parent IDs。

parent birth_tick 必須早於 child birth_tick。

---

# 18. Mutation

Phase 1 至少：

rare larger mutation

Mutation rate configurable。

Mutation RNG 必須走專屬 deterministic RNG stream。

不得：

if environment cold:
    mutate cold_resistance upward

Environment 不直接指定 mutation 方向。

Selection 必須透過 survival / reproduction 自然形成。

---

# 19. Deterministic RNG

建立 centralized RNG architecture。

至少建立 logical streams：

WORLD
RESOURCE
BEHAVIOR
MATING
MUTATION
DISASTER

不要讓一個 subsystem 多抽一次 RNG 導致所有其他 subsystem 的 random sequence 全部偏移。

Save file 必須保存必要 RNG state / stream version。

建立：

RNG_VERSION

未來若演算法改變必須 bump version。

---

# 20. Lineage

Lineage 必須是一級 simulation entity。

每次 population split / reproductive ancestry 至少可以追蹤來源。

建立 LineageRegistry。

至少記錄：

lineage_id
origin_tick
ancestor_lineage
founder information
population
genetic centroid / representative genome information

不要等 Phase 2 才加入 lineage。

# 21. Species Detection

Phase 1 建立第一版 deterministic species system。

不要：

每個 mutation = species

建議根據：

population clustering
genetic distance
gene flow / reproductive compatibility
minimum population
minimum persistence duration

產生：

SpeciesCandidate

Candidate 必須持續達到 threshold 一段時間，才正式：

SpeciationEvent

SpeciesRecord 至少包含：

species_id
scientific_name
origin_tick
ancestor_species
founding_lineage
status
extinction_tick optional
representative genome / trait statistics

Threshold 必須 configurable 並記錄在 SimulationConfig。

---

# 22. Scientific Naming

Phase 1 不允許依賴 LLM 命名。

建立 deterministic naming system。

輸入可包含：

species_id
lineage characteristics
seed
phenotypic characteristics

生成 Latin-style binomial name。

例如：

Velocipodus ruber
Microvorus minor

名字一旦 assign：

永遠儲存在 SpeciesRecord。

不得因為 population trait 後續改變而重新命名。

避免生成重複名稱。

建立 tests。

# 59. Biological Model Philosophy

This is artificial life inspired by evolution.

Do not claim scientific predictive accuracy.

However, simulation mechanics should respect the fundamental causal chain:

genome
→ phenotype
→ behavior / physiology
→ survival / reproduction
→ population genetics
→ divergence

Environment must not directly instruct genes how to mutate.

Evolutionary adaptation must emerge from differential reproductive success.
